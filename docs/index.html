Bare metal → ESXi → VMware Holodeck

Bare metal to a Holodeck lab through one API

I rebuild my Holodeck lab more often than I would like, and for the longest time that meant an evening in the iDRAC console with a hand-edited kickstart and an ISO that never quite matched the last one. GroundZero does that work through the server's BMC: it checks the hardware, installs ESXi unattended, verifies the result and prepares the host for Holodeck.

What it does

Every step runs through a versioned REST API, and the web UI and the CLI are both clients of it, so anything you can click you can also script.

Preflight

Reads the inventory over Redfish and checks CPU support, memory, disks, NICs, boot mode and the BIOS virtualisation settings against the Holodeck 9 requirements. It is read-only, so you can run it against a server that is still in production without anyone noticing.

Unattended ESXi install

Builds a custom ISO from the stock installer, serves it to the BMC as virtual media, boots it once and then verifies the build, IP, VLAN, uplinks and NTP. The VMFS datastore on the install disk is kept unless you ask otherwise.

The pipeline

Each step's output is the input of the next one, and the pipeline recommends what to run next. Reinstall the OS and everything read from the old one is marked out of date, so you are not preparing a host based on what it used to be.

Host preparation

Applies what Holodeck needs on the installed ESXi: MTU 9000, trunk and external port groups, NTP and a datastore. It then sends 9000-byte frames out of one uplink and back in the other, because the physical switch is usually the part nobody checked.

Holorouter

Uploads the Holorouter OVA, sets its network properties and waits for SSH. It turns out the Holorouter reads those properties once, on first boot, and ignores them after that... which I found out the slow way.

Credentials and certificates

Credentials are encrypted at rest and never returned by the API. BMC and ESXi certificates are pinned on first contact, and anything destructive asks you to type a confirmation first.

How it works

The web UI, the CLI and your own automation all drive the same REST API. Long-running work becomes a job with live progress, and each job keeps a diagnostics bundle with every BMC and ESXi call, minus the secrets.

  1. Register the serverAdd the BMC address and credentials. The BMC's TLS certificate is pinned on first contact.
  2. Describe the OSCapture a config set from a running ESXi host, or build one in the UI. The hostname and IP stay with the server.
  3. Preview, then installCheck the generated kickstart, then type the confirmation phrase. Nothing goes to the BMC before that.
  4. Follow the pipelineThe next step is always recommended, and a blocked step tells you which input it is waiting for.

Installing it

You need Python 3.12 and uv, or Podman or Docker if you would rather run the container.

# install and start (keep this running)
git clone https://github.com/djsincla/GroundZero.git
cd GroundZero && uv sync
uv run groundzero serve
uv run groundzero ui        # in another terminal

# register a server and check it (read-only)
uv run groundzero hosts add --bmc 198.51.100.11 --name esxi1
uv run groundzero preflight esxi1

# follow the recommended next step
uv run groundzero pipeline esxi1

The installation guide covers the network requirements, the container option and every step through to the Holorouter. Be aware that the BMC fetches the install ISO from your machine on TCP 443, so if a firewall sits between them, that is the first thing to check.
